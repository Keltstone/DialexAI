# Scribex in Continuous Integration (CI)

This document describes how Scribex behaves in CI environments, its hardened workflow architecture, pinned action SHAs, reproducible releases, and exit code conventions.

---

## Exit Codes

Scribex follows standard POSIX exit status semantics:

| Exit Code | Meaning | Description |
|-----------|---------|-------------|
| `0` | **Success** | All checks passed cleanly, or sync succeeded with no unresolved issues. |
| `1` | **Findings / Issues** | Issues were detected (e.g. stale/broken/dead anchors, unconfined paths, read-only file write refusal `write-refused`, or commit preconditions failed). |
| `2` | **Usage / CLI Error** | Invalid flags, unknown subcommands, or syntax errors. |

In CI pipelines, any non-zero exit code (`1` or `2`) will fail the step.

## Workflow Security Architecture

### 1. Two-Tier PR Architecture (`.github/workflows/scribex-pr.yml`)
To eliminate arbitrary code execution with elevated tokens:
- **Trigger**: Strictly `on: pull_request` (NEVER `pull_request_target`).
- **Top-level permissions**: Completely stripped (`permissions: {}`).
- **Job `check`**:
  - `permissions: { contents: read }`
  - Access to zero secrets (`secrets.*` is completely prohibited).
  - Evaluates contract deltas via `scribex check -base "origin/$BASE_REF" -report $RUNNER_TEMP/scribex-report.md`.
  - Publishes report as a temporary workflow artifact.
- **Job `comment`**:
  - `permissions: { pull-requests: write }`
  - **Zero checkout of untrusted PR code**: Checks out the trusted target base ref (`ref: ${{ github.base_ref }}`).
  - Downloads the pre-computed markdown report artifact.
  - Posts or updates the PR comment using `scribex comment -body-file ...`.
  - On fork PRs where tokens are read-only, `scribex comment` degrades gracefully to writing the report to `$GITHUB_STEP_SUMMARY` and exits 0.

### 2. Post-Merge Docs Sync (`.github/workflows/scribex-docs.yml`)
- **Trigger**: `on: push: branches: [main]` and `workflow_dispatch`.
- **Top-level permissions**: `permissions: {}`.
- **Protected Environment**: Job `docs` runs under the `environment: scribex-ai`. Secrets (`ANTHROPIC_API_KEY`, `ATLASSIAN_TOKEN`, `ATLASSIAN_USER`, `ATLASSIAN_URL`) are scoped exclusively to this protected environment.
- **Branch and PR Isolation**:
  - The bot NEVER pushes directly to the default branch (`main`).
  - Commits are pushed to an isolated branch prefix: `refs/heads/scribex/docs-<short_sha>`.
  - Pull requests are opened via `gh pr create` with title `docs: scribex sync for <short_sha>`.
  - AI-drafted sections carry `<!-- @scribex:ai -->`.
- **Repository Requirements**:
  1. The GitHub repository setting **"Allow GitHub Actions to create and approve pull requests"** must be enabled (under *Settings > Actions > General > Workflow permissions*).
  2. Branch protection and `CODEOWNERS` must mandate human review before merging docs PRs. The bot never approves or merges its own pull requests.

### 3. GitLab CI Configuration (`.gitlab-ci.scribex.yml`)
- Runs merge request pipelines with `GIT_DEPTH: "0"`.
- Secrets (`ANTHROPIC_API_KEY`, `ATLASSIAN_TOKEN`) must be configured as **Protected + Masked** variables in *Settings > CI/CD > Variables* so MR pipelines from untrusted branches or forks never receive them.
- *Phase 3 Note*: Automated MR creation on default branch push is reserved for Phase 3.

## Reproducible Builds and Release Scripts

All scripts reside in `scribex-ai/scripts/`:

### `scripts/build.sh <VERSION>`
Builds multi-platform release binaries with reproducible toolchain flags:
- `CGO_ENABLED=0`
- `go build -trimpath -buildvcs=false -ldflags "-s -w -X main.version=${VERSION}"`
- Respects `SOURCE_DATE_EPOCH` for deterministic timestamps.
- Targets:
  - `linux/amd64`, `linux/arm64`
  - `darwin/amd64`, `darwin/arm64`
  - `windows/amd64`, `windows/arm64`
- Generates `dist/SHA256SUMS`.

### `scripts/repro-check.sh [VERSION]`
Validates build reproducibility by compiling two independent builds in distinct temporary directories with isolated `GOCACHE` and `TMPDIR` environments and comparing SHA-256 hashes. Fails on any mismatch.

### `scripts/sbom.sh [--cyclonedx]`
Generates a Software Bill of Materials (SBOM):
- If `cyclonedx-gomod` is installed: generates `dist/sbom.cdx.json`.
- Otherwise: generates a standard toolchain and module manifest `dist/sbom.txt`.
- When `--cyclonedx` is requested without `cyclonedx-gomod` installed, exits non-zero with `install cyclonedx-gomod for CycloneDX`.

### Release Signing
> [!NOTE]
> Release artifact signing will be integrated via Cosign once KMS release keys are configured.
> ```bash
> cosign sign-blob --key <key-path-or-kms> --output-signature dist/scribex_<os>_<arch>.sig dist/scribex_<os>_<arch>
> cosign verify-blob --key <pubkey-path-or-kms> --signature dist/scribex_<os>_<arch>.sig dist/scribex_<os>_<arch>
> ```
> *Signed releases do not exist yet.*

## Safe Automated Commits: `scribex sync -commit`

The `-commit` flag instructs `scribex sync` to commit updated documentation files automatically when anchors are synchronized.

### Semantics
- **Minimal staging**: Scribex only commits files that Scribex itself modified during this specific run (`git commit --only -- <changed...>`).
- **Preserves existing work**: Unstaged changes to code or other documents remain unstaged. Staged WIP commits in the index remain staged.
- **Literal paths**: All paths are passed literally with pathspec guards to prevent glob expansion on unusual filenames.

### Preconditions for `-commit`
Scribex checks several preconditions before attempting to commit:
1. **Git available**: The `git` executable must be present on the system `PATH`.
2. **Attached HEAD**: Commits cannot be created in a detached HEAD state.
3. **No pre-dirty documentation files**: If a doc file that Scribex needs to modify was already dirty (modified in index or working tree) before Scribex ran, Scribex aborts the commit to avoid overwriting uncommitted user work.
4. **Resolved author identity**: Git commit requires a committer identity. Scribex will refuse to commit if no identity is found.

### Identity Environment Variables
In headless CI environments where standard `git config` is unset, you can provide identity through environment variables:
- `SCRIBEX_GIT_NAME`: The committer and author name (e.g., `Scribex Bot`).
- `SCRIBEX_GIT_EMAIL`: The committer and author email (e.g., `scribex-bot@example.com`).

These take precedence when `git` author configuration is not set globally or locally in the repository.

### CI Security: Hooks Neutralized
To guarantee deterministic execution and protect CI environments against arbitrary code execution from untrusted repository hooks, `scribex sync -commit` neutralizes git hooks by configuring `core.hooksPath` to `/dev/null` (or `NUL` on Windows). Repository-defined client-side hooks (`pre-commit`, `commit-msg`, etc.) are not executed during automated sync commits.
